# Как писать симулятор (docs/SIM_API.md)

Проект: «Макро» — современный интерактивный учебник макроэкономики (vanilla ES-modules, без сборки, без внешних библиотек и CDN).
Каждое из 15 упражнений классического учебника — это **один файл** `app/js/sims/<id>.js`, который рисуется внутри общей рамки
(`app/js/views/sim.js` — заголовок, чек-лист «Задание», кнопки «Сбросить / Сравнить / PNG / Во весь экран», соседние модели).

Эталонная реализация: **`app/js/sims/ex6-1.js`** (кейнсианский крест). Читайте её первой — структура и качество, к которым надо стремиться.

## Контракт модуля

```js
// app/js/sims/ex6-1.js
export function mount(root, env) {      // root — пустой <div class="simview__stage">; env = { id, lab, topic, tasks:[строки], reduced, bus, toast }
  …построить UI в root…
  return {
    charts: [chart1, chart2],   // (необязательно) включает кнопки «Сравнить» (пунктирный «след» прежних кривых) и «PNG»
    reset() { … },              // (необязательно) включает кнопку «Сбросить»: вернуть исходные значения из оригинала
    compare() {…}, clearCompare() {…},   // (необязательно) свой «До/после» вместо автоматического chart.snapshot()
    destroy() { … },            // снять таймеры, rAF, слушатели, chart.destroy()
  };
}
```
Маршрут для проверки: `http://localhost:8800/index.html#/lab/<id>` (сервер уже запущен в корне репозитория; перезапускать не нужно).
Ошибка в `mount` не роняет страницу — рамка покажет сообщение; следите за консолью.

## Библиотеки (читайте заголовки файлов — там полные описания)

- **`app/js/core/dom.js`**: `h('div.cls#id', {attrs,onclick,style:{'--c':'var(--d1)'},html}, ...kids)`, `s()` для SVG, `fmt(n, decimals)` (ru-форматирование с узким пробелом и «−»), `clamp lerp map smooth`, `plural`, `toast`, `bus`, `reduced()`, `rng(seed)`.
- **`app/js/ui/controls.js`**: `simLayout(root)` → `{controls, stats, stage, notes}`; `slider`, `seg`, `toggle`, `stat` (анимированное число + дельта к `base()`), `panel`, `presets`, `button`, `callout`, `legend`, `dtable`, `field`, `figure`, `symHTML('C_a')`.
- **`app/js/ui/plot.js`**: `createChart(host, {x:{min,max,label,ticks,fmt}, y:{…}, aspect, maxH, margin})` → `line / area / point / vline / hline / text / arrow / bars`, `update()`, `snapshot()`, `setDomain()`, `enableHover()`, `toPNG()`. Элементы — замыкания на состояние модели: поменяли состояние → `chart.update()` → всё плавно «переезжает». Подписи: `'Y_0'`, `'r^*'`, `'M/P'` (индексы/степени авто-набираются).
- Токены и классы: `app/css/tokens.css` (цвета `--d1..--d6`, `--ink*`, `--surface*`, `--accent`, шрифты), `app/css/ui.css` (все компоненты выше). Не редактируйте общие файлы (см. правила).

## Раскладка

`simLayout(root)` создаёт две колонки: слева липкая панель параметров (`L.controls`), справа показатели (`L.stats`), графики (`L.stage`; класс `.is-2` — два графика рядом), заметки/таблицы (`L.notes`). На телефоне (<980px) основной график **закрепляется сверху**, а ползунки прокручиваются под ним — поэтому первый `figure` должен быть главным графиком и не выше ~300px на телефоне. Если модели нужна своя раскладка (например, большая схема), можно не использовать `simLayout`, но корневому элементу дайте класс `sim` и `sim--<id>`.

Свои стили — только строкой CSS, вставленной в `<head>` один раз (`<style id="css-<id>">`), все селекторы с префиксом `.sim--<id>`. Цвета — только токены (`var(--d1)`, `var(--ink-3)`, …), чтобы работали обе темы (тёмная «Night Atlas» и светлая «Paper»).

## Что должно быть в каждой модели

1. **Та же математика, что в оригинале**: те же уравнения, те же исходные значения по умолчанию, те же выходные показатели (что оригинал показывал в таблице/графике — то и тут). Диапазоны ползунков можно расширить относительно оригинала (где модель остаётся осмысленной), но исходное состояние = исходное состояние оригинала, а результаты для исходных/типовых изменений должны совпадать с оригиналом до знака.
2. **Без кнопок «Произвести расчёт»**: всё пересчитывается «вживую» при движении ползунка. Кривые плавно переезжают, числа анимированно перекатываются, рядом видно изменение («▲ +2 000»).
3. **Сценарии (presets)** под задания упражнения (`env.tasks` показаны в рамке над моделью): одна кнопка = одно типовое возмущение из задания.
4. **До/после**: таблица с «исходно / сейчас / изменение» (как «Перенесите в тетрадь таблицу… до и после»), пунктирные «следы» прежних кривых.
5. **Пояснение с цифрами**: короткий блок «как получено» — формула с подставленными текущими числами и словесный вывод (что произошло и почему) на русском, языком учебника, без воды.
6. **Подписи осей/кривых как в учебнике** (Y, E, r, M/P, AD, AS, IS, LM…), единицы измерения.
7. Доступность: у каждого ползунка подпись; у графика `title`; состояние не только цветом; работает с клавиатуры.
8. Телефон 390px: никакого горизонтального скролла страницы, нет обрезанных подписей, график читаем; тёмная **и** светлая темы выглядят хорошо.
9. По возможности одна «изюминка», которая делает модель живой (перетаскиваемая точка/кривая, анимация потока, кнопка «проиграть» для динамики, интерактивная подсказка при наведении) — но только если это помогает понять экономику.
10. Тон интерфейса: спокойный, точный, «прибор», а не «игра». Без эмодзи, без лишних градиентов и теней. Числа — моноширинные.

## Правила для параллельной работы

- Создавайте/меняйте **только свои файлы**: `app/js/sims/<ваш id>.js` (и при необходимости общий хелпер вашей группы `app/js/sims/_<имя>.js`). Общие файлы (`core/`, `ui/`, `css/`, `views/`, `index.html`, `sw.js`) **не редактируйте** — если чего-то не хватает, реализуйте локально в своём файле, а предложение по библиотеке напишите в итоговом сообщении.
- Git не трогайте (никаких add/commit/checkout/stash) — коммитит координатор.
- Не запускайте свои серверы на порту 8800; пользуйтесь существующим. Для своих временных файлов — `/tmp`.
- Никаких сетевых запросов, внешних библиотек, CDN, внешних шрифтов. `localStorage` не нужен.
- Итог — короткий отчёт: что сделано, какие отклонения от оригинала и почему, пожелания к общим компонентам.
